# Accounts API

Account applications and accounts: opening at core banking, and funds holds for Payments.

## Security controls

What this project does to stay secure: each control, what would go wrong without it, the threat it stops, and where to find it in the code. The platform-wide picture: [Architectural and security features §2](../../../../doc/Architectural-And-Security-Features-Demoable-EWP-V3.md#2-security-features).

| # | Security control | If it were missing | Threat prevented | Where to look |
|---|---|---|---|---|
| 1 | Strict access-token validation: issuer, audience, lifetime, signature against the IDP's keys, and only `typ: at+jwt` access tokens (RFC 9068); original claim names kept (`MapInboundClaims = false`) | A token issued for another API, an ID token or an expired token would be accepted | Token confusion and replay across APIs (OWASP API2 Broken Authentication) | `AddJwtBearer` in [Program.cs](Program.cs) |
| 2 | Deny by default, the same in every domain API: every controller needs an authenticated caller on top of its own policy, and any other endpoint without a policy needs one too (fallback policy); only health and metrics are explicitly anonymous | A new endpoint added without an attribute would be public | Broken function-level authorization (OWASP API5) | `MapEwpApiControllers`, `DenyAnonymousByDefault` in [Program.cs](Program.cs); [ApiEndpointAuthorization.cs](../../../Common/WebUtilities/Security/ApiEndpointAuthorization.cs) |
| 3 | Step-up: account-opening decisions require a RECENT two-step sign-in (`amr` contains `mfa` and `auth_time` at most `Mfa:StepUpMaxAgeMinutes`, default 15, old) while `Mfa:Enabled` is on; outside Development the API refuses to start unless it is on | A stolen password alone would be enough to approve or reject; a session left open since a morning sign-in would still approve; a forgotten setting would silently switch the step-up off in production | Account takeover leading to fraudulent decisions; insecure defaults (OWASP A05) | [MfaStepUp.cs](../../../Common/WebUtilities/Security/MfaStepUp.cs), `stepUpPolicies` and `RequireMfaOutsideDevelopment` in [Program.cs](Program.cs) |
| 4 | Officer attributes and branch scope per request | Another branch's officer could open accounts | BOLA and excessive privilege (OWASP API1, API5) | [AccountOfficerAuthorization.cs](Authorization/AccountOfficerAuthorization.cs) |
| 5 | Cross-context separation of duties: the account officer is neither the initiator nor the Compliance approver | One person could approve compliance and open the account | Insider fraud | `EnsureOfficerMayAct` in [AccountApplication.cs](Domain/Aggregates/AccountApplication.cs) |
| 6 | Core-banking calls with an API key and an `Idempotency-Key`; a refusal is final, not retried | A retried request after a timeout could open a second account | Duplicated accounts | [CoreBankingClient.cs](Infrastructure/CoreBanking/CoreBankingClient.cs) |
| 7 | Payments may look up accounts only for a person allowed to initiate payments (`payment.initiate`) | Any caller could enumerate accounts | Data harvesting | Policy `PaymentAccountLookup` in [Program.cs](Program.cs) |
| 8 | Internal endpoints accept only the one machine client meant to call them (`client_id` pinned, not just the scope) | Any service holding the scope could post fake workflow steps (e.g. a forged "compliance approved" message) | Service impersonation and spoofed workflow events | Policies `AccountApplicationOpeningSubscriberWrite` / `AccountsCommandSubscriberWrite` in [Program.cs](Program.cs); [InternalAccountApplicationsController.cs](Controllers/InternalAccountApplicationsController.cs), [InternalFundsCommandsController.cs](Controllers/InternalFundsCommandsController.cs) |
| 9 | Problem responses without internals (a `traceId` only; details are logged on the server) | Stack traces, SQL or exception messages would reach the caller | Information disclosure that helps an attacker (CWE-209, OWASP A05) | [ApiExceptionHandler.cs](Controllers/ApiExceptionHandler.cs) |
| 10 | Per-caller rate limits (person, machine client, IP), 429 with `Retry-After`; the subscribers' internal endpoints too (machine-client budget); counted per instance (R-14) | One caller, or a stolen token, could flood the API for everybody | Unrestricted resource consumption (OWASP API4) | [RateLimiting.cs](../../../Common/WebUtilities/Security/RateLimiting.cs), `AddEwpRateLimiting` in [Program.cs](Program.cs) |
| 11 | Own least-privilege database user `ewp_accounts_api`: its own database only, no DDL | A compromised API or leaked connection string would expose other contexts' data or let the schema be changed | Lateral movement and blast radius of a breach | [EwpServiceDbUsers.sql](../../../../db/EwpServiceDbUsers.sql) |
| 12 | HTTPS only (HSTS outside Development) and host filtering (`AllowedHosts`) | Tokens could travel over plain HTTP; a forged `Host` header could poison generated links | Interception (OWASP A02) and host-header attacks | `UseHsts` in [Program.cs](Program.cs); `AllowedHosts` in [appsettings.Development.json](appsettings.Development.json) |
| 13 | Funds are reserved only on an account of the initiating staff member's branch (`ACCOUNT_NOT_IN_BRANCH` otherwise), checked under the account's row lock - the payment screen's branch-filtered search is not the control | Anyone allowed to initiate payments could move money from another branch's customer by calling the Payments API directly | BOLA through the payment command path (OWASP API1) | `RefusalToHold` in [Account.cs](Domain/Aggregates/Account.cs), [InternalFundsCommandsController.cs](Controllers/InternalFundsCommandsController.cs) |
| 14 | No full account numbers in logs: the BSB and the last four digits only | Account numbers would spread into log shippers and observability platforms with other access and retention rules | Exposure of financial identifiers (OWASP A09, privacy) | [LogMasking.cs](../../../Common/Observability/LogMasking.cs), [FundsCommand.cs](Application/Commands/FundsCommand.cs), [OpenDueAccount.cs](Application/Commands/OpenDueAccount.cs) |
| 15 | The core-banking system's address is checked at start-up: an absolute URL without credentials; outside Development https, a host listed in `CoreBanking:PermittedHosts`, and no loopback, private or link-local address; its client follows no redirects | A wrong or tampered address (e.g. a cloud metadata endpoint) would receive the API key and customer data; a redirect could move the call elsewhere | Server-side request forgery by configuration (CWE-918) | `ExternalEndpoint` in [Program.cs](Program.cs); [ExternalEndpoint.cs](../../../Common/WebUtilities/Security/ExternalEndpoint.cs) |
| 16 | Parked Outbox messages: `GET v1/accounts/outbox/parked` (no payload) and `POST …/{id}/resend` - only through the Operations Journey API acting for an operator (delegated token, `act` pinned), with `outbox.view` / `workflow.reprocess`, a reason (10-500 characters) and recent MFA; one atomic `UPDATE` resends the SAME message only if it is still parked; who, when and why are kept on the row | A message parked after a Kafka outage would block its record for good, or be "fixed" by hand in the database, unrecorded and possibly twice | Broken function-level authorization (OWASP API5); repudiation | [OutboxController.cs](Controllers/OutboxController.cs), [ParkedOutbox.cs](Infrastructure/Messaging/ParkedOutbox.cs), [DelegatedTokens.cs](../../../Common/WebUtilities/Security/DelegatedTokens.cs) |
| 17 | Container image: built only by CI from a commit, chiseled non-root runtime (no shell, files read-only to the process), base images pinned by tag and digest, scanned before it is published (HIGH / CRITICAL with a fix, or any secret, fails); settings and secrets come from the environment; the database connection string is no longer in `appsettings.json` - none of them is in the image. | A developer-built or tampered image could run in an environment; a credential in a layer stays in the registry for good; a shell in the image helps an attacker who gets in | Supply-chain tampering (OWASP A08); vulnerable components (A06); hard-coded credentials (CWE-798) | [Dockerfile](Dockerfile), [.dockerignore](../../../../.dockerignore), [container-images.yml](../../../../.github/workflows/container-images.yml), [doc/Containers.md](../../../../doc/Containers.md) |
