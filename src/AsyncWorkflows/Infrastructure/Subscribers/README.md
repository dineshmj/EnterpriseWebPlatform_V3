# AsyncWorkflows.Infrastructure.Subscribers

The shared subscriber pipeline every worker runs on.

## Security controls

What this project does to stay secure: each control, what would go wrong without it, the threat it stops, and where to find it in the code. The platform-wide picture: [Architectural and security features §2](../../../../doc/Architectural-And-Security-Features-Demoable-EWP-V3.md#2-security-features).

| # | Security control | If it were missing | Threat prevented | Where to look |
|---|---|---|---|---|
| 1 | Offsets committed only after processing; permanent failures dead-lettered with the reason, transient ones retried | A crash could lose a message, and a poison message could block the partition | Lost events; denial of service by one bad message | [KafkaSubscriberHostedService.cs](KafkaSubscriberHostedService.cs), [MessageProcessing.cs](MessageProcessing.cs) |
| 2 | Required settings and both key files validated at start-up (`ValidateOnStart`, the keys actually read), no defaults; the client ID, the IDP's and the API's addresses come from configuration only (https) | A worker could run with no key, a broken one or no dead-letter topic | Misconfiguration becoming a silent gap | [SubscriberServiceCollectionExtensions.cs](SubscriberServiceCollectionExtensions.cs) |
| 3 | Machine token cached and renewed shortly before expiry | Every message would request a token from the IDP | Self-inflicted denial of service on the IDP | [CachedM2MTokenClient.cs](CachedM2MTokenClient.cs) |
| 4 | Liveness and readiness with no internals in the response | A stuck worker would keep its partitions; a probe response could leak details | Silent outage; information disclosure | [SubscriberHealth.cs](SubscriberHealth.cs) |
| 5 | No client secret: the worker proves itself with a one-time `private_key_jwt` assertion (aud = the IDP's issuer from its discovery document, 60 s, new `jti`); its token is DPoP-bound (RFC 9449) - an unbound token is refused - and every API call, each retry included, carries a new proof (method, address, `ath`) from a handler inside the resilience pipeline. The token request itself is never retried automatically (a resent assertion would be a replay); a DPoP nonce request is answered once. The client key and the DPoP key are two separate EC P-256 keys (the same key twice stops the start-up) | A shared secret in settings, or a machine token copied from a log or a proxy, would let anyone act as the worker until it expires | Client impersonation; stolen-token replay (OWASP API2; Threat-Model R-9) | [MachineKeys.cs](MachineKeys.cs), [CachedM2MTokenClient.cs](CachedM2MTokenClient.cs), [DPoPMachineTokenHandler.cs](DPoPMachineTokenHandler.cs), [SubscriberServiceCollectionExtensions.cs](SubscriberServiceCollectionExtensions.cs); UT [AsyncWorkflows.Infrastructure.Tests](../../../../tst/dotnet/AsyncWorkflows.Infrastructure.Tests/Subscribers) |
